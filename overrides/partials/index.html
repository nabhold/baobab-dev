Why BAOBAB

✅

Deterministic builds

config/versions.yaml is the single source of truth for every tool version, resolved to a lock file before Docker ever runs. Identical inputs produce identical images — no drift between what one engineer has and what another does.

📦

Multi-arch by default

Every published image supports linux/amd64 and linux/arm64 via Docker Buildx, built from the same Dockerfile — Apple Silicon and ARM64 cloud runners get a native image, not an emulated one.

🔄

Identical everywhere

Local Docker, VS Code Dev Containers, GitHub Codespaces, and CI all run the same image — onboarding a new engineer and reproducing a CI failure locally use the exact same environment.

🛡

Verified before it ships

Every image is validated by an automated build-time verification pass — toolchain, runtime configuration, and user permissions are checked before publication, not after engineers hit a broken environment.

Supply-chain integrity, not an afterthought

Every published image is signed, attested, and scanned before it reaches a registry — verifiable by anyone, not just trusted by default.

🔑

Keyless signing

Every image is signed via Cosign using GitHub OIDC — no long-lived signing keys to leak or rotate.

📜

SLSA provenance

Build provenance is attested and published alongside every image, tracing it back to the exact workflow run that built it.

📋

SPDX SBOM

A full software bill of materials is generated and attested for every image, so you know exactly what's inside.

🔎

Trivy CVE gating

Images are scanned for known vulnerabilities before publication, with severity gating enforced in CI.
